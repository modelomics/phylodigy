# Glossary

| Term | Meaning |
| --- | --- |
| Alignment underidentification | A local structural orbit that this representative solver cannot distinguish. It is not a count of globally optimal mappings or a homology claim. |
| Annotation | Paper-grounded label or description attached to an existing graph target without changing its structural identity. |
| Artifact | One immutable model, paper, repository revision, or composite evidence record. |
| Canonical graph | Graph representation invariant to incidental node names, module paths, mapping order, and valid operator-argument reorderings. |
| Graph alignment | A replayable, direction-relative structural comparison with pinned endpoints, neutral unmatched-object lists, explicit add/remove operations, and cost bounds. Version zero is not a general graph edit distance. |
| Character matrix | Corpus-by-character representation built from discovered structural signatures and their multiplicities or states. |
| Closed model | Model whose executable computation graph is unavailable. Its paper can supply document claims, not a synthetic graph. |
| Contact | Non-vertical relationship that may explain copied components or other shared structure. |
| Convergence | Similar graph structure reached without demonstrated transfer. |
| Digest | Content hash that pins an artifact, graph, paper, annotation, or method configuration. |
| Discovery method | Generic graph algorithm plus parameters used to enumerate structural characters. |
| Evidence channel | Independently retained source of graph, source-history, document, citation, or curated provenance. |
| Four-point condition | Quartet condition satisfied by additive tree distances. |
| Frontend | Framework adapter that lowers an observed model graph into the canonical graph record. |
| Graph edit distance | Cost of a minimum sequence of graph transformations under a declared symmetric event model. |
| Graph profile | Canonical operators, directed edges, observed attributes, provenance, fingerprints, and discovered structures for one execution scope. |
| Graph region | Algorithmically bounded subgraph with exact supporting nodes and edges. It has no built-in technique name. |
| Homology | Shared ancestry hypothesis supported by inherited code or aligned graph structure. |
| Missingness | Unavailable, opaque, or uncovered graph evidence; never interpreted as absence. |
| Neighbor joining | Distance-based method that returns an unrooted tree and is exact for additive input. |
| Open model | Model with an observable executable graph under at least one documented frontend and probe. |
| Operator identity | Frontend-supplied operation schema or stable open-vocabulary label. |
| Paper document | Normalized text plus identity and digest, independent from graph observations. |
| Phylodigital | Adjective for lineage analysis or lineage hypotheses concerning digital artifacts, as in “phylodigital tree.” |
| Phylodigy | The project and the noun for phylodigital lineage analysis. |
| Phylogenetic character | Corpus-derived structural signature used in character-based inference. It is not selected from a catalog. |
| Probe | Input and guard specification under which a runtime graph was observed. |
| Pseudometric | Distance that may assign zero to distinct graphs because their finite feature representations collide. |
| Structural character | Anonymous content-derived neighborhood, graphlet, path, region, repetition, or edit signature. |
| Temporal gate | Requirement that a possible source predates a target before directional influence is considered. |
| Vertical backbone | Tree-like component inferred from compatible structural evidence and time constraints. |

## Terms to avoid

Do not describe a manually maintained feature list as the model genome. Do not
call a class-name match, config-key match, or paper phrase a structural
observation. Do not treat paper non-mention or incomplete tracing as absence.

Avoid calling a fingerprint pseudometric an evolutionary branch length. Avoid
calling a bounded alignment cost a graph edit distance merely because its
bounds close; objective-scoped optimality requires endpoint validation. Avoid
calling left-to-right add/remove operations historical gains or losses. Avoid
calling heuristic scores probabilities or an inferred edge proof of causation.
